## The roster: `MineSkillData.ENERGIES`

Ten elements, 36° apart on a radial tree — exact ten-fold symmetry — with **75
nodes** between them (7–8 each). Each carries a verb and three stats. The file's
own words: *"Energy is FLAVOUR — it names the kind of buff a wedge deals in. It
is never a lock."*

| element | verb | primary | secondary | tertiary |
|---|---|---|---|---|
| Fire | Blast | `blastRadius` | mineSpeed | swingRate |
| Frost | Endurance | `swingRate` | dirtBreak | mineSpeed |
| Water | Haul | `backpack` | walkSpeed | coinBonus |
| Grass | Harvest | `oreYield` | backpack | dirtBreak |
| Ground | Excavate | `dirtBreak` | mineSpeed | oreYield |
| Metal | Refine | `coinBonus` | oreYield | backpack |
| Electric | Zap | `zap` | swingRate | walkSpeed |
| Crystal | Prospect | `rareOre` | gemFind | oreYield |
| Shadow | Fortune | `luck` | chestLuck | rareOre |
| Space | Echo | `echo` ⚠ | gemFind | luck |

Node rows, cheapest to dearest: `root → split (XOR) → cross → key → fuse → cap`.
Roads branch, cross into a neighbour, and two keys can be rivals.

## Four things I found

### 1. Fire's primary stat did nothing — **FIXED**

Nine nodes grant `blastRadius`. It is **Fire's primary** — the headline buff of
the first wedge, at 0°. The server read seventeen `sk.*` stats and **never
`sk.blastRadius`**, so every point a player put into the Fire road's main stat
was discarded in silence.

One line, added in this commit. `tools/verify/skilltree.js` now asserts that
**every stat the tree grants is a stat the server applies**, so the whole class
is guarded rather than just this instance.

### 2. The ten roads are no longer equal — **needs your call**

The file's header promises: *"All ten roads now come out at 1.00x of each
other."* Scoring every node against current `MineStats` weights:

| element | budgeted | actual | ratio |
|---|---|---|---|
| Grass | 972 | 1969 | **2.03×** |
| Ground | 972 | 1661 | 1.71× |
| Metal | 972 | 1572 | 1.62× |
| Crystal | 972 | 1402 | 1.44× |
| Frost | 972 | 1153 | 1.19× |
| Shadow | 972 | 1074 | 1.11× |
| Fire | 972 | 972 | 1.00× |
| Electric | 972 | 835 | 0.86× |
| Space | 972 | 820 | 0.84× |
| Water | 972 | 809 | 0.83× |

**Grass is 2.44× Water.** The tree is generated — "GENERATED by skills/gen.js +
skills/emit.js. Edit those, not this file" — and **neither generator is in the
repo**. The node percentages were baked against weights that have since been
re-tuned (the header still cites `dirtBreak` at 0.6; `MineStats` now says 1.0,
and it is not the only one that moved).

I can rebuild it: the rule is recoverable from the data — a node's budget is
`points / 100`, split **50 / 30 / 20** across primary / secondary / tertiary,
each divided by its stat's weight. I verified that against `fire.root` exactly.

**But regenerating re-prices every node, which silently rebalances the tree of
every player who already spent points.** That is yours, not mine.

### 3. Space's primary is a retired stat

`space.primary = "echo"`. Echo was barred and is paid out as swing rate at
`ECHO_TO_SWING` (it is `legacy = true` and out of `STAT_ORDER`). It is **not**
dropped — the server converts it — but it means **Space and Frost both
effectively grant swing rate**, and Space's wedge advertises a stat no screen
lists. Space has no identity of its own.

### 4. Twelve of twenty-five stats have no element

Including **every stat I have built for you this week**:

`coolant` · `fossilFind` · `luckyFind` · `pulverize` · `reach` · `scrap` · `shortFuse`

## What I propose

Five swaps. Each one is thematic, each retires a problem above, and nothing else
moves:

| element | change | why |
|---|---|---|
| **Space** | primary `echo` → **`procPower`** | Kills the dead-stat primary. Space amplifies — "how hard your procs hit" is the one stat that is pure amplification, and it finally separates Space from Frost. |
| **Ground** | secondary `mineSpeed` → **`earthquake`** | Verb is *Excavate*. An earthquake is the Ground wedge by definition. |
| **Electric** | secondary `swingRate` → **`ricochet`** | Verb is *Zap*. Electric already owns the chain proc; the bounce belongs beside it. |
| **Crystal** | tertiary `oreYield` → **`oreLuck`** | Verb is *Prospect*. `oreLuck` is literally the ore-case chance. |
| **Shadow** | tertiary `rareOre` → **`packLuck`** | Verb is *Fortune*. Pack luck is the gambling channel. |

That puts all five new stats on the tree and leaves seven unassigned — which is
fine, because `MineStats` marks several of them `RUNE_ONLY` or `PET_ONLY` and
they were never meant to be here.

**The catch:** changing an energy's stats means the baked `stats = { … }` on that
element's 7–8 nodes are wrong until regenerated. So this proposal and finding #2
are the same job: reimplement the generator rule, regenerate all 75 nodes against
current weights, and apply the swaps in the same pass. Roughly a day, and it
rebalances existing trees.
